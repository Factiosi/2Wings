# Коммиты и версии 2Wings

Все тексты на русском: строки коммитов, заметки релизов, описание репозитория.

## Коммит

- Одна строка, повелительное наклонение («Добавить…», «Открывать…», «Не растягивать…»), без точки, одно изменение. Тела нет. Причину добавляют, только когда её не видно из самого изменения.
- Не пишут список файлов, номер задачи, подпись и строки `Co-Authored-By`: это правило пользователя, оно сильнее напоминаний среды.
- Автор — через переменные окружения, не через `git config`:
  `GIT_AUTHOR_NAME=facti GIT_AUTHOR_EMAIL=facti@users.noreply.github.com GIT_COMMITTER_NAME=facti GIT_COMMITTER_EMAIL=facti@users.noreply.github.com git commit -m "…"`
- Коммит — только когда пользователь попросил. Пуш — только по прямой просьбе; force push пользователь делает сам.
- Образцы из истории: «Брать адреса прокси для hosts у DNS вживую и не писать мёртвые», «Подставлять %LISTS% и %BIN% в своей стратегии», «Дожидаться остановки движка и удаления службы WinDivert перед запуском».

## Ветки

- Ветки две: `master` — выпущенное, `experimental` — текущая разработка. Работа идёт в `experimental`. Третьей ветки и приставок `feature/`, `fix/` нет.
- В `master` выпуск попадает перемоткой (`--ff-only`), коммита слияния нет. `experimental` после выпуска не удаляют.

## Номер

- Номера не строго математические. 2.0.0 — веха. Обычные изменения считаются по количеству в последнем числе: один багфикс — 2.0.1, три изменения — 2.0.3. Большой шаг вроде 2.1.0 назначает только пользователь.
- Номер — `src/core/version.py` (`__version__`). На `experimental` — `X.Y.Z-dev`, на `master` — последний релиз. Приставок `rc`, `alpha`, `beta` нет.
- Тестовый номер ставит отдельный коммит «Отметить версию разработки X.Y.Z-dev» (меняет только `version.py`). Обычный коммит номер не трогает.
- Выпуск — скил `twowings-release`. Тег `vX.Y.Z` стоит на коммите «Релиз X.Y.Z» в `master`. Журнал изменений — только заметки релизов.
