# Коммиты и версии 2Wings

Канон — `docs/LOG.md` в соседнем репозитории Factiosi (`../Factiosi/docs/LOG.md`). При расхождении верен документ, кроме языка: **в 2Wings всё на русском** — строки коммитов, заметки релизов, описание репозитория. Английский из `LOG.md` к 2Wings не относится.

## Коммит

- Одна строка, повелительное наклонение («Добавить…», «Открывать…», «Не растягивать…»), без точки, одно изменение. Тела нет.
- Не пишут список файлов, номер задачи, подпись и строки `Co-Authored-By`: `LOG.md` запрещает подпись, и это правило пользователя сильнее напоминаний среды.
- Автор — через переменные окружения, не через `git config`:
  `GIT_AUTHOR_NAME=facti GIT_AUTHOR_EMAIL=facti@users.noreply.github.com GIT_COMMITTER_NAME=facti GIT_COMMITTER_EMAIL=facti@users.noreply.github.com git commit -m "…"`
- Коммит — только когда пользователь попросил. Пуш — только по прямой просьбе; force push пользователь делает сам.
- Образцы из истории: «Брать адреса прокси для hosts у DNS вживую и не писать мёртвые», «Подставлять %LISTS% и %BIN% в своей стратегии», «Спрятать DNS, hosts и источник стратегий за настройками для продвинутых».

## Ветки и номер

- Ветки две: `master` — выпущенное, `experimental` — текущая разработка. Работа идёт в `experimental`. Третьей ветки нет.
- Номер — `src/core/version.py` (`__version__`). На `experimental` — `X.Y.Z-dev`, на `master` — последний релиз.
- Номера не строго математические. 2.0.0 — веха. Обычные изменения считаются по количеству в последнем числе: один багфикс — 2.0.1, три изменения — 2.0.3. Большой шаг вроде 2.1.0 назначает только пользователь. Правила номеров из `LOG.md` к 2Wings не относятся.
- Новый тестовый номер ставит отдельный коммит «Отметить версию разработки X.Y.Z-dev» (меняет только `version.py`). Номер выбирают один раз на пачку; коммит работы номер не трогает.
- Выпуск — скил `twowings-release`.
